# Interface styling

This guide owns shared component boundaries, native adaptation rationale and reference-comparison procedure. Use [AppKit conventions](../CONVENTIONS.md#appkit-behavior-and-accessibility) for accessibility, appearance and deferred dialogs. Current dimensions, colors, typography and component variants belong in source.

## Token ownership and changes

Use the [design catalogues](../Sources/CodexGUI/App/Design/) for named design inputs and [UI components](../Sources/CodexGUI/UI/Components/) for reusable composition. Change a named input at its owner. [Typography configuration](../Sources/CodexGUI/App/Design/TypographyConfiguration.swift) supplies independent UI, document-content and code bases through the [role catalogue](../Sources/CodexGUI/App/Design/TypographyTokens.swift). Page/content sizing remains independent. Chat prose and the Files Markdown preview select the UI scope, including preview headings and inline-code size; fenced code retains its code scope. A token existing in a scope does not establish that every reading surface consumes it. Appearance preferences persist locally; role bindings refresh retained controls, while prepared Markdown and transcript caches include the configuration in their identity. Preserve selection, draft content, navigation state and control presentation, including icon-only buttons, when refreshing typography. Components consume named semantic roles; role derivation, font selection and paragraph metrics belong in the typography catalogue and resolver. Use the existing binding’s update callback for font-dependent constraints, and refresh retained attributed content through the same observation lifecycle.

[Color preferences](../Sources/CodexGUI/Persistence/ColorPreferences.swift) select per-appearance profiles, and the [palette](../Sources/CodexGUI/App/Design/ColorPalette.swift) derives semantic colors from them. Resolve colors in the owning view's effective appearance and refresh retained native layers, field editors and prepared content when preferences change; preserve interaction and navigation state during the refresh. Components select named color roles; opacity, state blending and contrast-paired surfaces belong to the central color policy. A shared resolution helper does not make a local literal or palette derivation a semantic role. Retain opaque contracts for search editors, QR quiet zones and contrast-dependent content.

Theme presets and [local Appearance choices](settings.md#appearance) select UI, content and code font families independently for each appearance. The [font resolver](../Sources/CodexGUI/App/Design/AppKitFontResolver.swift) follows each preset's fallback list and retains the typography size and weight rules; an unavailable family falls back to the applicable native font. Refresh retained text when either the profile or effective appearance changes.

Font weight expresses emphasis independently of size and family. The [typography roles](../Sources/CodexGUI/App/Design/TypographyTokens.swift) own weight intent; the [native resolver](../Sources/CodexGUI/App/Design/AppKitFontResolver.swift) selects installed faces. Several intents may resolve to the same face in a static family. Use exact system variation axes for app text and CSS face matching for named families; do not synthesize bold to manufacture distinctions. Native widget metrics and artwork retain explicit platform selections. UI interaction states preserve their role's weight. Explicit fixed control line boxes remain exact; glyphs can extend into the surrounding control padding.

Markdown emphasis is semantic and survives restyling without inferring it from a font's bold trait. Chat inline code inherits its surrounding emphasis; file headings retain their heading weight even around nested strong text or code. Code uses its own family while inline code retains its context's size rule. Terminal emphasis remains separate from prose emphasis. The shared output renderer consumes streamed control sequences, retains emphasis through typography and color refresh, and preserves the original source for whole-output copying. Bundled KaTeX owns mathematical faces and formula layout; the central typography policy supplies its resolved size and source-fallback metrics, and the shared semantic foreground supplies its ink. Math and diagrams use the same offline WebKit lifecycle, cancellation, bounded preparation and native vector display. Their prepared content includes typography and theme configuration in cache identity. Mermaid receives the resolved UI family, diagram typography roles and semantic diagram colors before measurement; flowchart node labels retain independent metrics because they determine the renderer's node geometry. The Appearance mode miniatures retain fixed neutral illustration fills so their modes remain identifiable independently of a custom profile; their accent and selection state still use semantic theme colors. Renderer geometry and template-icon lettering may retain fixed metrics where required to fit their artwork; document the constraint at the owning renderer. Reference measurements do not establish complete parity for those engines.

The Settings shell title uses a locally licensed OpenAI Sans Semibold face. Its embedded license prohibits redistribution, so the font data is not bundled or stored in this repository. Supply an authorized `OpenAISans-Semibold.woff2` in `~/Library/Fonts`; the [local font registrar](../Sources/CodexGUI/App/Design/LocalTypographyFonts.swift) registers it for the app process. A normally installed face is used directly. Font installation is required to reproduce the reference title family; without it, the resolver uses the existing system fallback. Terminal text uses the Code family while sizing from the UI base; source, diff and fenced code size from the code base.

Choose token roles by purpose: equal values do not establish a shared design rule. Compute derived relationships rather than maintaining independent copies. Keep shape and layout responsibilities separate, and leave artwork coordinates, native metrics and operational tolerances with their owners unless they represent shared design decisions. Pure layout helpers consume measured inputs rather than measuring native views or fonts.

Menu row geometry derives from its resolved title and supporting-text recipes and retains a minimum interaction target; native fields also reserve the selected face’s glyph height. [Action menus](../Sources/CodexGUI/UI/Components/Controls/DesktopActionMenu.swift) reuse the shared rows, surface, keyboard navigation and dismissal lifecycle for queue actions and viewer zoom. Open menus preserve selection and focus while their presentation resizes.

Validate configuration fit separately from available-space behavior. A valid configuration still needs truncation, reflow, scrolling or collapse when space shrinks. Measure in the component's coordinate space; a clipped viewport, intrinsic request and final frame can differ.

Reuse presentation configurations as well as their resolution machinery. Semantic component roles should reference the [shared text configurations](../Sources/CodexGUI/App/Design/TypographyTokens+Text.swift) and shared palette bindings when their size behavior, emphasis, line metrics, surface and interaction contracts match. Keep useful context names as aliases rather than copying the configuration. Review small differences before creating another configuration; central placement alone does not justify a difference. Retain a distinct configuration when its requirement cannot be represented by the shared one, with the non-obvious constraint documented beside its owner. Artwork, renderer layout, contrast pairs and opaque surfaces can impose such constraints.

## Component ownership

A reusable component owns its complete appearance, composition and interaction states. Feature adapters supply semantic content, selection, operation state and callbacks. They must not independently restyle the same variant. Infrastructure helpers support complete components; assembling the same helpers repeatedly in features is not shared component ownership.

[DesktopStyledButton](../Sources/CodexGUI/UI/Components/Controls/DesktopStyledButton.swift) uses app-owned presentations while retaining AppKit activation and keyboard routing. Callers choose a semantic presentation and size, supply content and actions, and publish enabled, selected and loading state; loading alone does not disable an action. The component owns typography, content layout, painting and interaction feedback. Do not override its font or drawing, replace its cell, or apply native button styling. Put reusable visual differences in the component’s presentation policy, and keep feature-specific visibility and operation eligibility with the caller. Parent rows own action revelation; buttons own their own hover and focus feedback.

Action tooltips share [the tooltip presentation](../Sources/CodexGUI/UI/Components/Controls/DesktopTooltip.swift) through [native control adaptation](../Sources/CodexGUI/UI/Components/Controls/DesktopControlTooltip.swift). Preserve native action routing and keep transient panels passive; focus, pointer exit, dismissal and owner retirement belong to the shared lifecycle. Show shortcut badges only for actions wired in the local app. Give each hover target one tooltip owner: toolbar items with custom views leave presentation to those views, row-wide native tooltips must not cover custom actions, and content embedded in a tooltip-owning control must not register a second native tooltip.

[Project previews](../Sources/CodexGUI/Features/Navigation/ProjectHoverCard.swift) keep metadata consistent with explicit project info. Hovering must not select a project or take keyboard focus, and actions retain the project identity captured when the preview opens. The nonactivating card tracks pointer entry independently of key-window status. A short dismissal delay bridges the gap from the row to the card, and dismissal rechecks that the pointer has left both before closing.

[Turn previews](../Sources/CodexGUI/UI/Transcript/TurnNavigationRail.swift) retire when their anchor or an ancestor is hidden. Full-view pane transitions can hide a conversation without delivering a pointer-exit event, so hidden anchors must also reject new preview presentation.

Domain eligibility, persistence and asynchronous request identity remain feature responsibilities. Native composition reuse must not merge independent decision lifetimes. Apply [DRY](../CONVENTIONS.md#dry-principle) when deciding whether callers share a contract.

Find existing controls and compositions in [UI/Components](../Sources/CodexGUI/UI/Components/) before adding one. Follow [placement conventions](../CONVENTIONS.md#responsibility-boundaries) to select the owning source.

## Native adaptation rationale

Each main window needs its own toolbar identifier: AppKit synchronizes items between toolbars sharing an identifier even when configuration autosaving is disabled. The application supplies toolbar composition, so autosaving remains disabled.

Expanded images and diagrams share a child-window host so their overlay covers native window chrome without changing the parent layout. An expanded diagram retains its presentation during restyling when its document identity, occurrence position and source remain the same; prepared artwork refreshes in place while zoom and scroll position remain intact. Replacing the occurrence or retiring its document dismisses the viewer. The shared presentation follows parent movement and resizing, isolates accessibility while open and restores the previous responder when dismissed. Image export preserves the bounded local source’s original encoded bytes; diagram export retains its vector format. Both use the shared native save-panel lifecycle. Closing a viewer cancels pending reads and unaccepted sheets; an accepted file write completes independently off the main actor. Main windows allow AppKit to refresh keyboard navigation as transcript cells and tools enter or leave the hierarchy. The [transcript collection](../Sources/CodexGUI/UI/Transcript/ConversationCollectionView.swift) anchors forwarded Tab commands at its focused descendant so native navigation continues through reply actions.

Composer editors paint their enclosing surface color so AppKit can erase the previous insertion point. Popover hosts establish their preferred geometry before attaching constrained content, so initial layout never evaluates padded controls against a zero-width surface. Popover shadows need transparent panel padding to avoid clipping; adding a second native window shadow darkens the result. Blur and shadow kernels require rendered comparison. Expanded images apply a passive Gaussian background filter in the parent view hierarchy while the transparent child owns the semantic veil and interaction. This avoids adding a system material’s tint to the selected theme. The public filter samples its parent layer tree; acceptance must cover native chrome separately, along with resize, appearance changes and teardown.

App-owned text-entry sheets use [the shared prompt](../Sources/CodexGUI/UI/Components/Dialogs/DesktopTextEntryPrompt.swift) and dialog shell to keep heading, input and action typography under app ownership. Their completion path commits the active field editor before accepting a value and preserves composition handling, Escape cancellation and one-time response delivery.

Rich Mermaid rendering uses a WebKit-prepared vector PDF for AppKit display because AppKit's direct SVG decoder loses Mermaid CSS, text positioning and markers. Exports retain SVG. WebKit preparation retains geometric precision to keep SVG measurement and export independent of staging transforms. Keep that renderer adaptation separate from the shared typography roles and retain measured browser differences without numeric size or coordinate compensation. Offline dependency installation and rebuild instructions belong to the [Markdown resource guide](markdown-resources.md).

Transcript site icons make external requests to Google's favicon service, with LinkPresentation origin metadata as fallback. Requests use the host or origin rather than a link's full path. Keep this network behavior explicit when changing [favicon loading](../Sources/CodexGUI/UI/Markdown/WebLinkFaviconLoader.swift); it is separate from offline diagram rendering.

## Reference and acceptance

For reference-driven work, record the reference revision, content, control state and appearance preferences. Distinguish measured text and geometry from inferred font identity, point conversion and behavior. Use native AppKit points for nominal CSS pixel dimensions, while recognizing that glyph rasterization, shadows and native chrome require visual acceptance.

Use paired captures with matching content and state. Cover both appearances at wide and narrow widths, including hover, focus, selection, disabled controls, multiline drafts, long code, tables and retained tool tabs. Do not infer descendant styles, syntax colors or window chrome from container styles. Unobserved reference appearances remain unverified.

Exercise continuous Appearance color changes both before and after opening and dismissing long settings menus. Color-only edits preserve font metrics; font overrides, preset changes and appearance changes still refresh retained typography. Dismissed picker menus must retire their presentation work.

Reference accounts and screenshots do not establish backend capabilities or authorize unrelated controls. Populate identity and usage from the connected account. Keep unavailable actions out of the working capability claims. Follow [validation](validation.md#native-and-live-acceptance) for evidence interpretation and [native QA](native-qa.md) for launched-app procedures.
