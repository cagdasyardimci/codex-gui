# Application architecture

This guide records boundaries and invariants that changes must preserve. Use [conventions](../CONVENTIONS.md#file-organization-and-ownership) for placement rules and the [application source](../Sources/CodexGUI/Application/) for concrete models, transitions and effect implementations.

## State transitions

The application uses Model View Intent (MVI) with one canonical store per checkout/session. Views render presentations and send intents; reducers synchronously change values and describe effects. Backend, filesystem and persistence work belongs to runtime services. Keep task handles, subscriptions and native view state outside the canonical model. Supply clocks and identifiers through captured actions rather than creating them in reducers.

Compose cross-feature transitions before publication and reserve accepted effects before notifying observers. Otherwise observers can see partially applied transitions or submit conflicting work. Persistence must preserve accepted-write order and support draining before checkout removal or termination.

Backend history belongs to Codex. Local persistence owns drafts, preferences and recovery records; views must not edit Codex conversation files. Capture next-turn preferences at submission so later control changes cannot retarget accepted work. Settings-specific persistence follows [Settings](settings.md#configuration-ownership).

The Tauri workspace database validates its application identity before migrating schema versions. A single transaction advances the schema and its version markers. Add persisted feature records with their first consumers in the [storage module](../desktop/core/src/storage.rs). The [write coordinator](../desktop/core/src/storage/writes.rs) reserves effects before publishing acceptance, orders writes per captured checkout, and retains failed payloads until an explicit retry. Drain scoped writes before closing their owner. A [draft save](../desktop/core/src/storage/drafts.rs) compares the expected durable revision inside the transaction and updates only changed fields. Independent draft lifetimes keep distinct storage identities. The [attachment store](../desktop/core/src/storage/attachments.rs) stages complete bytes before accepting durable draft references. Keep the profile’s store open while any lease is active. Recovery removes interrupted staging files and unowned blobs under the same exclusive ownership used for collection.

Image annotations belong to their composer attachment identity and persist with the draft. The [image comment canvas](../Sources/CodexGUI/UI/Images/ImageCommentCanvas.swift) stages edits locally; Save commits them to that captured draft without submitting a turn, while cancellation or retirement discards unsaved edits. Coordinates remain relative to the original image, independent of zoom and scrolling. [Context input construction](../Sources/CodexGUI/Application/Services/ComposerContextBuilder.swift) groups comments by the final image attachment order, including unannotated images when determining image numbers.

## Desktop IPC

The [Tauri host](../desktop/src-tauri/src/project_ipc.rs) accepts workspace requests from the local main document. It issues a workspace ID after a native directory selection and revalidates the captured filesystem identity before returning a snapshot. Selecting another directory retires the prior grant. Keep native paths and workspace authorization on the Rust side. Use [generated IPC types](validation.md#tauri-diagnostic-shell) for the WebView contract.

The [workspace subscription](../desktop/core/src/ipc/subscription.rs) attaches to the current snapshot under the same lock as publication. The host retains one projection and accepts one outstanding read from the current subscriber. The renderer applies adjacent revisions and attaches again after a gap. Reload attaches to the latest snapshot and retires the previous subscription.

[Stream batches](../desktop/core/src/ipc/stream.rs) keep text in order within each item and flush pending deltas before item or turn completion. Incremental reads send the latest change. A snapshot carries the assembled text so a renderer can resume without replaying notifications. Replacing the workspace clears its visible transcript and retires its stream updates.

The [desktop navigation runtime](../desktop/src-tauri/src/navigation.rs) validates restored project authority against the saved directory identity and reads chat history through Codex. The editor persists text against the original draft identity, including when navigation has already changed. Clearing a project retires its grant and returns to the unsent draft. Retry reacquires writer ownership for the captured chat and preserves its draft and readable history.

The [account flow](../desktop/src-tauri/src/navigation/account.rs) opens the Codex-provided ChatGPT authorization page through the system browser. Codex owns callback handling and credentials. The app matches completion to the original connection and login before refreshing the account and models. Cancelling or retiring a connection invalidates its pending attempt.

The [composer runtime](../desktop/src-tauri/src/navigation/send.rs) checks the displayed draft and checkout before dispatch. Starting a chat binds the original draft and assigns a fresh unsent draft in the same transaction. Recovery evaluates saved receipts against history before allowing a second Send. [Interaction cards](../desktop/src-tauri/src/navigation/interactions.rs) use the pending request from the original connection and chat even when another chat is visible. The [question reply presenter](../desktop/core/src/ipc/question_reply.rs) is shared by transcript and chat previews. It displays the ordered questions and answers when the entire envelope validates and preserves other text as stored.

The [composer attachment boundary](../desktop/src-tauri/src/composer_ipc.rs) captures the checkout and draft before it opens a file dialog or starts reading input. The [attachment store](../desktop/core/src/storage/attachments/composer.rs) preserves draft text while staging image bytes and checkout file references. Send verifies the displayed attachment order before admitting the draft. A recorded image can be reused from its owning turn after the submission journal establishes its sent reference.

The [image annotation editor](../desktop/frontend/src/ImageAnnotationEditor.svelte) stores points as fractions of the displayed image in its original proportions. Save checks the captured image digest and the original annotations before updating the draft. The [composer serializer](../desktop/src-tauri/src/navigation/composer_attachments.rs) numbers comments by attachment order, including images with no comments in that count.

The [composer context picker](../desktop/frontend/src/ComposerContextPicker.svelte) uses the shared watched path index and the [native catalog](../desktop/src-tauri/src/composer_context_ipc.rs) for enabled skills and included project context. The plus action preserves the draft and selection. An @ choice removes only the captured UTF-16 token and stages the context in the same draft transaction. A retired draft or changed text invalidates the choice.

The [composer settings](../desktop/src-tauri/src/navigation/composer_settings.rs) resolve effort and speed against the effective model's advertised choices. Configured Permissions reads the backend configuration. Presets set the turn's policy explicitly, and Full Access confirmation requires the original checkout, chat and selection revision. Send captures the resolved settings before dispatch, so later edits apply to the next Send.

[Project Context](../desktop/src-tauri/src/navigation/project_context.rs) stores one revisioned document per checkout. Project defaults fill unset composer choices and Send resolves a saved skill against the active checkout's enabled catalog. Prompt insertion checks the captured project revision and draft text. Bookmarks validate the owning chat and fetch the saved turn by identity, using lightweight reference pages when the turn is outside the resident transcript.

The [checkout diff](../desktop/core/src/git.rs) reads the working tree against a captured Git baseline and keeps raw path identities in Rust. The [diff IPC](../desktop/src-tauri/src/diff_ipc.rs) accepts file identifiers issued by the current list. It verifies the checkout before returning a patch and invalidates file identifiers when the list refreshes.

[Repository comparisons](../desktop/core/src/git/comparison.rs) resolve refs before listing changed paths. Branch and recent-commit selectors use separate reads. A file detail is requested by its issued identifier and checked against both native endpoints of a rename before publication. [Patch export](../desktop/core/src/git/comparison/export.rs) returns Git's original bytes and revalidates the entire captured index or working-tree comparison before publication. Pinned object pairs can [reuse comparison results](../desktop/core/src/git/comparison/cache.rs) when Git can use the target tree's attributes and verify the effective diff policy.

[Project file access](../desktop/core/src/files.rs) keeps native paths in the checkout scope and exposes a separate display name and handle. Reads use an open directory as their starting point, reject links at each path component, and verify the file and checkout identities before returning a bounded snapshot. [Saving](../desktop/core/src/files/save.rs) compares the captured disk revision again before replacing a file and leaves editable text with the caller on failure. Filesystem locking protects cooperating writers. The operating system can still allow an external tool to replace a directory entry between the final check and publication.

## Ownership and recovery

The [managed worktree store](../desktop/core/src/worktree.rs) preserves AppKit's versioned per-worktree records. Managers acquire the records directory's existing `.lock` before reading authority or changing records and hold it through each Git operation and its resulting record update. Keep that lock file in place across process exits and upgrades. An absent `.authority` document grants AppKit authority. Tauri's beta profile initializes its own records directory with an explicit Tauri grant. The Mac handoff will verify an AppKit build that checks this grant under the same lock before publishing a Tauri grant for the existing records directory.

The [worktree manager](../desktop/core/src/worktree/lifecycle.rs) captures the source's committed HEAD and records the prepared directory's native identity before asking Git to create a checkout. Source index and working files stay with the original checkout. The manager verifies native identity, Git registration, and branch before activating a task checkout or binding it to a reported Codex conversation. [Recovery](../desktop/core/src/worktree/lifecycle/recovery.rs) advances a preparation after a failed Git response only when the original directory and committed base can still be verified.

The [runtime owner registry](../desktop/core/src/workspace/owners.rs) reserves accepted writes by captured checkout and blocks cleanup while execution or writes remain. A cleanup reservation excludes new runtime work on the same checkout. [Project switching](../desktop/src-tauri/src/navigation/parked.rs) keeps active runtimes connected in the background. [Stop All and Quit](../desktop/src-tauri/src/navigation/quit.rs) interrupt each captured owner and drain accepted writes before completing. [Exit evidence](../desktop/core/src/storage/attachments/exit_recovery.rs) distinguishes turn completion from command exit and survives connection retirement and relaunch. A newly registered runtime invalidates older read-only recovery before it can modify that evidence.

[Worktree removal](../desktop/core/src/worktree/lifecycle/removal.rs) requires a cleanup reservation for the verified checkout. Git status includes ignored files before removal. The journal retains the branch and task binding and records removal after the checkout path and Git registration are both gone.

Displayed selection and execution ownership are independent. An accepted first message appears in project navigation using its captured request identity while the backend creates the conversation. The assigned thread replaces that row atomically; a failed preparation retires it without changing an independently opened draft. Every asynchronous result must validate its captured workspace/session, connection generation, request identity and relevant thread/turn. Deferred UI actions must retain their original target rather than follow later selection. Shared eligibility rules serve presentations and reducers, with admission checked again at reduction.

The [Tauri checkout state loop](../desktop/core/src/workspace.rs) reserves preparation before publishing a pending chat. It captures the visible draft, attachment leases, and run settings even if the debounced save is still pending. [Thread preparation](../desktop/core/src/workspace/prepare.rs) validates the backend checkout and commits the original draft binding and attachments together before adopting the navigation row. A newer saved revision keeps its edits. A replaced connection retires its pending preparations and preserves the drafts for explicit recovery.

Ordinary chats share their checkout and app-server while retaining independent execution state. Managed task checkouts have separate stores and connections. Cleanup and quit decisions must inspect all executions, including hidden chats. A working-tree comparison can contain edits from several chats.

An explicitly confirmed application quit attempts to stop active work with a bounded grace period and drains accepted local writes before retiring backend connections. Missing terminal evidence remains recorded for recovery. Ordinary Stop All requires authoritative task outcomes. Keep the main window available when quitting is cancelled or saving fails. Suppress automatic last-window termination while a quit is pending so closing the confirmation cannot initiate another quit. In Tauri, native Close and Quit share the [quit coordinator](../desktop/src-tauri/src/navigation/quit.rs). The [exit recovery store](../desktop/core/src/storage/attachments/exit_recovery.rs) retains distinct turn and command evidence until matching terminal history arrives.

An interrupted turn does not prove command cancellation. The [Tauri execution tracker](../desktop/core/src/workspace/execution.rs) keeps unresolved command identities after turn completion or connection retirement. Only matching terminal command evidence clears them. Disconnects, relaunches and incomplete history must not clear uncertain outcomes or automatically resend possibly accepted work. Recovery records must become durable before starting a turn. Saved running history alone is insufficient evidence to adopt live execution ownership.

The [Tauri submission path](../desktop/core/src/workspace/submission.rs) commits the captured input, stable client message ID, and protected attachment references before admitting bytes to app-server. Stop and connection retirement invalidate queued writes. The writer revalidates the captured checkout at the pipe. An unsent receipt releases journal-owned attachments and preserves the draft. A possibly sent request keeps its journal and attachment ownership for reconciliation. For a direct turn, the first confirmed reply or matching user-message event records acceptance, transfers attachment ownership to the sent message, and retires the submitted revision in one transaction. A later edit takes precedence over draft retirement.

The [Tauri interaction router](../desktop/core/src/workspace/interactions.rs) keeps approvals and questions with their original chat and connection. A response uses the exact request ID, validates the offered decision or requested permission subset, and preserves the order of each question’s answers. A reply remains reserved after possible delivery until server resolution or connection retirement. Either event cancels a reply that is still queued.

[Submission recovery](../desktop/core/src/workspace/recovery.rs) can retire a reservation left before dispatch. Once dispatch was possible, it requires unambiguous evidence for the captured checkout and client message ID. Queue recovery checks ordered queue pages before reading history for unresolved receipts. A missing or conflicting match leaves the request and attachments available for reconciliation.

Routine [Tauri queue reads](../desktop/core/src/codex/browse/history/queue.rs) use a checkout-validated chat summary and ordered queue pages. Only an explicit unsupported-method response makes the server queue unavailable as a capability. An acknowledged add retires only its submitted draft revision and retains queue-owned attachments. A matching user message transfers that ownership to sent references before clearing the queue’s claim. The add request relies on the last accepted active turn and carries the thread and input. Codex controls dispatch once it receives that request.

[Tauri queue editing](../desktop/core/src/workspace/queue.rs) reserves an empty composer for its captured entry. If Codex consumes the entry, the edited composer becomes a regular unsent draft with its attachments. Updates validate the captured entry and reorder validates the captured order against the current queue. Both use queue pages to reconcile changes.

Queue deletion releases local queue references only after Codex confirms removal of the captured entry. A disappeared entry retains its references until consumption or deletion is proved. Independent drafts and sent messages retain their references.

Resume asks Codex to start the captured queue entry only while its thread is idle. Codex arbitrates concurrent turns. A rejection or uncertain reply keeps the receipt and attachment references for reconciliation.

The [local follow-up queue](../desktop/core/src/workspace/queue/legacy.rs) is available after an explicit unsupported response. It retains FIFO order and the settings captured before dispatch. A failed or interrupted turn or a replacement connection requires an explicit Resume. A possibly sent head keeps its place until matching history settles it.

[Queued steering](../desktop/core/src/workspace/queue/steering.rs) saves the captured input and active turn before seeking to remove a server entry. Only confirmed deletion permits steering the original input. A lost delete or steer reply leaves the receipt reserved. Recovery uses the same client message identity and, for steering, requires a match in the captured turn. A definitive steering rejection leaves the detached input and attachments available to restore into an empty draft.

The [Tauri queue controller](../desktop/src-tauri/src/navigation/queue.rs) keeps its pending operations and queue reads with the original chat across selection changes and WebView reload. The conversation’s saved queue preference decides how the composer sends an active-turn follow-up. The queue panel and empty composer Resume the same captured head.

The [AppKit queue importer](../desktop/core/src/storage/attachments/appkit_drafts/queues.rs) copies queued attachment ownership and imports server receipts for reconciliation by client message identity. It keeps the original queued entry and the independent draft when the import includes an unfinished edit. Saved local work starts paused. Resume can dispatch that work in order once the chat is idle and its server queue is empty.

[Resuming a Tauri chat](../desktop/core/src/workspace/resume.rs) reserves its routes before requesting writer ownership because Codex may dispatch queued work immediately. Early events stay with the captured thread and become actionable after the reply confirms its checkout and identity. A competing writer leaves the scoped history available for reading. Reconcile active turns and command exits from backend evidence when writer ownership is reestablished.

Distinguish a known rejection from an uncertain submission. A cross-app writer lock is a known rejection; reading its saved history must not adopt another client's turn. Retry reestablishes ownership without resending the prompt. Preserve submitted drafts until acknowledgement, restoring them only if the resulting empty draft remains untouched; newer edits and independent draft lifetimes take precedence.

The composer selects speed from the current model’s service tiers. A saved tier that the selected model does not advertise resolves to Standard. A directly submitted turn or a locally dispatched follow-up uses the tier captured with that submission.

The first message starts a turn; only an active turn with an accepted turn identity can queue follow-ups. Queues belong to their original conversation. On servers supporting the experimental queue API, the server owns durable ordering and automatic dispatch; the GUI refreshes every page after invalidations and never runs a competing dispatcher. Checkout ownership and connection generation scope every operation. Stable client identities, persisted acceptance journals and server receipts prevent automatic replay after uncertain writes or relaunch. Local queues remain available when the server explicitly rejects the read API; older local buffers migrate only after Resume because adding to an idle server may immediately start work. Queue persistence shares ordered draft writes and attachment ownership, and consumed entries transfer their attachments to conversation references before removal. Interruptions, failures and disconnects preserve pending follow-ups paused; restored queues also require explicit Resume. Resume starts a pending input as a new turn, with a queue-level action and an empty-composer action. Reordering and editing retain identity and reject stale or reserved entries. Editing uses the normal composer without overwriting an occupied draft; consumption of an edited server entry preserves its unsent draft. Per-row steering captures the active turn and, for server-owned entries, requires confirmed deletion before steering the original encoded input. A durable handoff journal prevents replay after lost replies or relaunch; ambiguous deletion or steering outcomes remain reserved for reconciliation, while a definitive steering rejection retains the detached input for explicit recovery. Turning queueing off routes new active-turn follow-ups through ordinary steering; its preference is conversation-scoped. Captured model, effort, permissions, collaboration mode and service tier remain sidecar metadata for server-owned entries because queue requests encode input only; automatic server dispatch uses server thread settings. See [server queue effects](../Sources/CodexGUI/Application/Runtime/WorkspaceEffectRunner/WorkspaceEffectRunner+ServerQueue.swift) for reconciliation and migration.

Clearing the project from an unsent new chat retains its current draft in memory while returning the source session to an unselected project; submission still requires a project. Shared persistence and cross-project navigation must preserve project/thread identities. Matching titles, paths or visible selection cannot substitute for those identities. Archive, deletion and checkout removal must revalidate their captured targets and report partial success without replaying confirmed mutations. Archiving hides the captured chat from navigation while the request is pending, retaining canonical history and drafts so a failure restores the row. Confirmed removal retires older sidebar reads before refreshing the list.

The [sidebar](../desktop/src-tauri/src/navigation/sidebar.rs) indexes chats by checkout and thread identity. Project names, pins, unread marks and ordering belong to the desktop store. Codex owns chat titles. Opening a chat in another project verifies the target checkout and thread before adopting the selection together.

Protocol-specific handling belongs to [CLI lifecycle safeguards](cli-compatibility.md#protocol-lifecycle-safeguards); deferred native confirmations follow [AppKit conventions](../CONVENTIONS.md#appkit-behavior-and-accessibility).

## Presentation

Voice uses the primary composer action when the draft is empty and voice chat is available. Stop and queue resume take precedence. Voice joins the selected writable chat and creates a thread from the new-chat composer. A live call retains the checkout, connection and thread that opened it. Changing the visible chat leaves the call running and moves its microphone, end-call orb and speaker controls into the window’s floating pill. The orb shows overlapping currents of light moving in opposite directions while listening. During playback the flow speeds up, speech peaks send ripples through the liquid and the orb expands within a fixed layout. Reduce Motion displays the orb without animation. Ending the call or losing its connection retires capture and playback. The thread owns the transcript, including voice exchanges that do not start a coding turn. The transcript displays spoken utterances and explicitly shared Markdown. Backend voice coordination and duplicate speech records stay out of the conversation. See [voice compatibility](cli-compatibility.md#voice-chat) for provider and history requirements.

During a call, plain text enters the realtime conversation. Drafts carrying attachments, selected project context or skills use the normal composer path, as do slash commands and queued-message edits.

Read Aloud plays the displayed response without adding a turn to the chat. Playback belongs to the response that started it and stops when that response loses its presentation owner. The [playback runtime](../Sources/CodexGUI/Application/Runtime/ReadAloudRuntime.swift) coordinates backend completion with local audio playback. See [CLI compatibility](cli-compatibility.md#transcript-speech-and-result-feedback) for provider requirements.

Result feedback sends a one-time report for the original chat and turn, with logs excluded. If delivery is uncertain, the [feedback reducer](../Sources/CodexGUI/Application/Reducers/ResultFeedback/ResultFeedbackReducer.swift) reserves that turn against another submission to avoid duplicate reports.

Response actions remain available on loaded, finished turns while newer turns run, subject to each action's eligibility. User message metadata and actions appear on hover or action focus. Reserve their space so revealing them preserves the reading position. See [transcript routing](../Sources/CodexGUI/UI/Transcript/TranscriptViewController/TranscriptViewController+TranscriptRendering.swift) and [fork behavior](slash-commands.md#syntax-and-intent).

Tauri’s [transcript projection](../desktop/core/src/ipc/stream.rs) updates rows by stable item identity. Consecutive commands share a row scoped to their turn. Copy captures a completed response’s exact source. The [row action boundary](../desktop/src-tauri/src/transcript_ipc.rs) checks the checkout grant, chat, transcript generation and row revision before copying or inspecting image dependencies. Local image dependencies are checked against current contained bytes before reuse.

The [Tauri Markdown renderer](../desktop/src-tauri/src/transcript_ipc/markdown.rs) projects bounded assistant markup into typed nodes. The [document view](../desktop/frontend/src/MarkdownView.svelte) keeps submitted prompts and question replies as literal text. It renders assistant markup through ordinary text and elements, preserves readable source while streaming or beyond render limits, and displays raw HTML literally. It fetches declared local raster media through the scoped row grant and retires image URLs with the view. External link handoff requires a user action and rechecks the source row.

The [attachment preview](../desktop/src-tauri/src/transcript_ipc.rs) keeps attachment order in history and publishes labels with row-scoped identifiers. The host resolves each identifier against the captured item and grants it a bounded raster read from the checkout. It rechecks the item after the read, so a chat switch cannot deliver bytes to the new transcript.

Only the first user message in a finished turn can qualify for editing because the fork boundary is the whole turn. **Send** forks before that turn and submits the revision with its recorded attachments once selection of the fork is confirmed. The edited text is sent as a prompt even if it starts with a slash command. If selection fails or is superseded, the revised draft and attachments remain available in the fork. See the [revision reducer](../Sources/CodexGUI/Application/Reducers/Composer/ComposerCommandReducer+SentPromptRevision.swift).

AppKit owns focus, selection, scrolling and layout. Prepare parsing, file reads and expensive derived content away from the main actor, then install only the current render generation. Superseded preparation must check cancellation before parsing and again when admitted to native rendering, so rejected results do not consume the input event loop first. Cancellation and owner retirement must reject stale installation and dismiss transient UI. Reuse must preserve the reader's position and selection within one owner without carrying them into another conversation. Active-turn replies retain readable code and exact copy text while deferring syntax coloring until the turn settles, avoiding repeated highlighting of a changing response.

Input admission reads canonical ownership directly; account-only observers project account state without constructing transcript snapshots. Draft edits update canonical state synchronously and share the streaming publication batch, while the native editor updates action visibility immediately. Repeated content and visibility updates must preserve existing geometry without forcing native layout.

Generated question-reply envelopes are presentation input, not visible chat prose. The [user message presenter](../Sources/CodexGUI/Application/Presentation/UserMessagePresenter.swift) normalizes complete, valid envelopes for transcript bodies and previews while preserving the stored backend text. Incomplete envelopes and examples embedded in ordinary prose remain literal; multi-answer replies retain their original order and prompt styling.

Keep shared rendering separate from consumer lifetimes: a renderer owns its resource limits and output; its feature owns loading, cancellation and presentation. Preserve exact source identity for selection, copy and caching, including byte-distinct paths and Unicode spellings. Unsupported or over-budget rich content must retain readable source. Filesystem reads and writes must remain contained, bounded and cancellable; revision conflicts must preserve unsaved edits.

Do not duplicate canonical payload inventories in presentation caches. Sources, transcript activity and summaries may project the same records differently, but must agree on identity and outcomes. Activity-specific design decisions belong to [activity presentation](activity-presentation-design.md), and native adaptation rationale belongs to [interface styling](interface-styling.md#native-adaptation-rationale).

The tab pane belongs to the selected chat within its checkout session. Switching chats restores that chat's tab order, selection, and pane layout for the lifetime of the window. Reordering tools preserves the selected tab and its content. In full view, the chat stays at the start of the strip. A new chat gets its own tab set, which follows the first submission when the backend assigns a thread. File edits and pending closes keep their original tab owner across switches, and closing the window or quitting settles writes from hidden chats as well as the visible chat. See [tab pane ownership](../Sources/CodexGUI/App/MainWindowController/MainWindowController+ChatTools.swift).

## Project file search

The [Tauri path index](../desktop/core/src/files/index.rs) belongs to the selected checkout and is shared by its chats. Recursive search follows the existing visibility policy for dot names and generated directories. Enumeration uses the captured directory and skips symbolic links and junctions to follow the [scoped file access policy](../desktop/core/src/files.rs). Results carry native path identity independently of their labels and must obtain a fresh scoped file handle before opening. The [workspace grant](../desktop/src-tauri/src/project_ipc.rs) retires results when the checkout is cleared, switched or replaced.

The [native observer](../desktop/core/src/files/index/watch.rs) coalesces directory scopes and applies pending changes before the next search. Overflow, an ambiguous path or an index that may need previously capped entries triggers a clean scan. A save that preserves all discovered paths preserves the index revision. Searches rebuild while the native observer is unavailable.

## Recorded latest Git turn

Last Turn attributes reported edits to the selected task's turn. Checkout-wide diffs cannot establish that attribution when chats interleave edits, even to the same file. Retain the latest known editing-turn identity independently of resident transcript bodies; older loaded edits cannot replace it without trusted ordering evidence.

Missing or evicted reports differ from an authoritative empty report. Never substitute another turn's viewer snapshot or a working-tree diff for unavailable reports. Exact patch composition may cancel compatible reversals; incompatible or over-budget sequences retain reported patches without offering them as an applicable combined patch. Filter reports to the owning checkout without merging byte-distinct filenames.

Shell writes and child-thread edits require backend attribution before they can be assigned to a parent turn. Shared directories, filenames and timing are insufficient evidence. Isolated task checkouts or backend write attribution are required for complete coverage. The recorded turn identity must not become a second unbounded patch cache.

The [AppKit review reducers](../Sources/CodexGUI/Application/Reducers/Review/) and [review runtime](../Sources/CodexGUI/Application/Runtime/Review/) define Swift composition and comparison behavior, and [presentation](../Sources/CodexGUI/Application/Presentation/) defines counts and badges. Tauri binds [Codex file-change reports](../desktop/core/src/git/turn_edits/reports.rs) to the captured connection and thread. Totals and Changes share one [composed result](../desktop/core/src/git/turn_edits.rs), and export serializes that result without reading the checkout or loading Git references.

## Conversation content residency

Residency bounds retained conversation payload, rather than total process memory. Native attributed strings, image decoding and layout overhead have separate owners. Protected visible or active content may exceed the payload budget; background fetching must yield rather than evict that content.

Scrolling to the top of the transcript requests the next page of older content when available, with one request pending at a time. Loading older content preserves the visible reading anchor within the scrollable document bounds. Layout and programmatic navigation do not trigger history pagination.

Tauri’s [history pager](../desktop/src-tauri/src/navigation/paging.rs) retains the cursor under its connection, checkout and chat. It prepends turns by stable identity and retires pending reads on selection changes. The [transcript viewport](../desktop/frontend/src/transcriptViewport.svelte.ts) restores the visible row and its pixel offset after insertion or height changes. It measures mounted rows and keeps focused controls and selected text mounted beyond the ordinary window. The [payload budget](../desktop/core/src/ipc/stream/residency.rs) protects the reader’s viewport, selection, focus, and jump target while evicting distant turns. A saved reading anchor can use the turn rail to reload its evicted payload when the chat reopens.

Eviction must preserve navigation metadata and reading anchors. Preview reads leave transcript entries and reading position intact. Foreground navigation supersedes neighborhood work, and owner changes and manual transcript scrolling cancel obsolete navigation. Tauri’s [turn rail](../desktop/src-tauri/src/navigation/paging/rail.rs) keeps references independent of loaded turns. A preview reads the edge pages of an unloaded turn. A committed jump retires the preview and loads the complete target before inserting it in conversation order. Keep AppKit residency defaults and cost estimates in [ConversationCachePolicy](../Sources/CodexGUI/Application/State/ConversationCachePolicy.swift).
